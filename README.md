# stalzone-bot

Telegram-бот для STALCRAFT (STALZONE) на офіційному API: стежить за викидами й аукціоном
артефактів і пише в канал/групу/особистий чат.

## Що публікує бот

| Що | Коли | Ручний запуск |
|---|---|---|
| ⚠️ Викид почався / ✅ закінчився | одразу, як API це показав | — |
| 📦 Топ-10 артефактів, виставлених на аукціон після викиду | через 30 хв після кінця викиду (`TOP_LOTS_DELAY`) | `python -m app.cli top` |
| 📊 Дайджест ринку: зміна цін за добу | щодня о 20:00 за Києвом (`MARKET_DIGEST_HOUR`) | `python -m app.cli digest` |

## Ручний запуск звітів

Для повторного топу чи дайджесту поза розкладом. Працює **поруч із запущеним ботом**,
зупиняти його не треба.

```powershell
.\.venv\Scripts\python.exe -m app.cli top                  # топ лотів після ОСТАННЬОГО викиду -> у канал
.\.venv\Scripts\python.exe -m app.cli digest               # дайджест ринку зараз -> у канал
.\.venv\Scripts\python.exe -m app.cli digest --dry-run     # тільки показати в консолі, у канал НЕ слати
.\.venv\Scripts\python.exe -m app.cli top --region RU      # тільки один регіон (типово — усі з REGIONS)
.\.venv\Scripts\python.exe -m app.cli --help               # довідка
```

- **Спершу `--dry-run`**, якщо не впевнений: без нього повідомлення одразу йде в канал.
- **Ручний `digest` не зсуває розклад.** Він порівнює поточний ринок з останнім
  плановим зрізом, але нічого не зберігає — дайджест о 20:00 вийде як звичайно,
  і завтрашнє порівняння так само рахуватиметься за добу.
- **Ручний `top`** бере те саме вікно, що й автоматичний: 30 хв після кінця
  останнього викиду. Якщо 30 хв ще не минуло — рахує до поточного моменту.
- Код виходу: `0` — усе гаразд, `1` — звіт не вдалося зібрати (API лежить, немає
  даних про викид). Деталі — у повідомленні в консолі.
- Обидві команди обходять весь каталог артефактів (~100 запитів, ~20–30 с).

## Структура

```
app/
  config.py         — параметри з .env
  http.py           — загальний SSL-контекст для httpx (Windows + перехоплювальний TLS антивірус/проксі)
  stalcraft.py      — клієнт API гри, адаптивний до rate-limit
  tracker.py        — чиста логіка викидів: "що змінилося" -> список подій
  market.py         — чиста логіка ринку: зрізи цін, порівняння, розклад дайджесту
  auction.py        — обхід лотів аукціону по каталогу артефактів
  artifacts.py      — каталог артефактів (artifacts_catalog.json з офіційної бази EXBO)
  reports.py        — збір звітів (топ лотів, дайджест), спільний для бота й CLI
  storage.py        — зберігання стану (JSON, атомарний запис)
  notify.py         — форматування й відправлення повідомлень у Telegram
  single_instance.py— захист від другого екземпляра бота
  main.py           — цикл опитування й розклад
  cli.py            — ручний запуск звітів
  constants.py      — константи застосунку
tests/              — pytest
```

## Швидкий старт (Windows PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt

copy .env.example .env      # демо-креденшали для API вже в шаблоні, Telegram можна поки не заповнювати

pytest                      # запустити тести
python -m app.main          # запустити бота — без TG_TOKEN просто друкує статус у консоль
```

## Що далі

1. Демо-креденшали для API гри вже в `.env.example`, реєстрація не потрібна — можна одразу
   дивитися статус викиду в консолі.
2. Отримати токен бота у @BotFather; дізнатися, куди слати — id особистого чату, групи
   або каналу.
3. Заповнити `TG_TOKEN`/`TG_CHAT_IDS` в `.env`, перезапустити — сповіщення пійдуть у Telegram.
4. На боєвий сервер (`https://eapi.stalcraft.net`) — зареєструвати застосунок,
   отримати свої `client_id`/`client_secret`, замінити демо-креденшали.
5. Задеплоїти на завжди-живий хост (Oracle Always Free / VPS + systemd `Restart=always`,
   або Docker `restart: unless-stopped`) — не GitHub Actions cron, там мінімум 5 хвилин
   між запусками й короткий викид можна прозевати.

## Windows: SSL-помилка при запуску

Якщо бачиш `CERTIFICATE_VERIFY_FAILED` — це антивірус або мережа з HTTPS-інспекцією
підсовує свій кореневий сертифікат, якому довіряє Windows, але не список certifi,
яким за замовчуванням користується httpx. Вже починено в `app/http.py`
(додає системне сховилище сертифікатів Windows до списку довірених).
