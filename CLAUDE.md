# stalzone-bot — инструкции для Claude

Телеграм-бот: опрашивает официальный API STALCRAFT (STALZONE), ловит начало/конец
выброса и постит уведомление в Telegram-канал(ы).

## Как устроено

Строгая слоёнка, менять её нельзя без явной просьбы:

```
config.py     — настройки из .env (dataclass Config, инстанс `config`)
http.py       — общий SSL-контекст для httpx (Windows + перехватывающий TLS антивирус/прокси)
stalcraft.py  — HTTP-клиент игры. Знает только эндпоинт emission, умеет RateLimit из заголовков
tracker.py    — ЧИСТАЯ логика: (регион, старое состояние, ответ API) -> (список Event, новое состояние).
                Ни сети, ни файлов, ни времени. Всё новое поведение "что считать событием" — сюда.
storage.py    — состояние в JSON за интерфейсом get/set (позже SQLite, интерфейс не трогать)
notify.py     — отправка в Telegram напрямую через Bot API; без TG_TOKEN/TG_CHAT_IDS — только логирует
main.py       — цикл: poll_once по всем регионам -> diff -> broadcast -> sleep(адаптивная пауза)
market.py     — ЧИСТАЯ логика рынка: срезы цен, "обычная" цена за 7 дней, сигналы купить/продать
views.py      — ЧИСТЫЕ экраны меню в личке: данные -> View(text HTML, кнопки); тестируется без Telegram
auction.py    — обход лотов аукциона по каталогу артефактов (сеть)
reports.py    — сборка топа лотов и дайджеста, общая для main.py и cli.py
telegram_bot.py — тонкий слой aiogram: /start, кнопки, поиск текстом -> views.py
cli.py        — ручной запуск отчётов (`python -m app.cli top|digest [--dry-run]`)
tests/        — pytest (чистая логика, respx для API, feed_update для aiogram)
```

Меню в личке читает СОХРАНЁННЫЙ дневной срез из state, а не рынок вживую: живой обход —
~30 с и ~100 запросов на каждое нажатие. getUpdates может слушать только один процесс
на токен (иначе 409) — ещё одна причина для single_instance.

Правило: `tracker` остаётся без побочных эффектов — это то, что реально покрывается тестами.
Любую логику с датами/временем передавать в него аргументом, а не читать внутри.

## Команды (Windows PowerShell)

```powershell
.\.venv\Scripts\Activate.ps1
.\.venv\Scripts\python.exe -m pytest -q      # тесты
.\.venv\Scripts\python.exe -m app.main       # запуск бота (нужен заполненный .env)
```

Python 3.12, venv в `.venv`. `.env` не коммитится, шаблон — `.env.example`.

## Факты про API STALCRAFT (сверено вживую curl'ом и рабочим прогоном, не только по докам)

- Базовые URL: демо `https://dapi.stalcraft.net`, боевой `https://eapi.stalcraft.net`.
  Домены `*.stalcraft.net` и `*.stalzone.com` в проверке оба работали одинаково — держим
  `stalcraft.net`, он и в докой странице, и в `.env.example`.
- **Авторизация — "Secret Based Authentication"**: заголовки `Client-Id` / `Client-Secret`
  на каждый запрос. Никакого OAuth-обмена/refresh не нужно — этот режим специально для
  приложений, которым не нужны данные конкретного игрока (нам подходит: emission — публичные
  данные). Демо-пара из документации (`Client-Id: 1`, `Client-Secret: E98cm6J9NNjTQopph0c2eIXNKafg4R1Cjz0TZh2D`)
  открытая и общая на всех тестирующих — не приватная, менять не обязательно на dapi,
  но не полагаться на неё как на секрет.
- Выброс: `GET /{region}/emission`. Регион **нечувствителен к регистру** — `/eu/emission`
  и `/EU/emission` оба дали 200 на демо. Более ранняя заметка "обязательно строчными" была
  перестраховкой из чужого враппера, не подтверждённым требованием API.
- Ответ emission: `{ "currentStart"?, "previousStart"?, "previousEnd"? }`, ISO-8601.
  **На демо-сервере `currentStart` фейковый и скользит вместе с реальным временем** —
  каждый новый запрос выглядит как "выброс только что начался". Это особенность демо-данных,
  не баг tracker: для боевого сервера ожидаются настоящие редкие циклы.
- Rate limit подтверждён по заголовкам: `X-RateLimit-Limit: 400`, окно ~60 секунд
  (`X-RateLimit-Reset` — unix-мс). `main.py` читает эти заголовки и подстраивает паузу
  адаптивно (`_next_delay`), не полагаясь на фиксированный интервал.
- Регионы: `GET /regions` -> `[{"id":"RU","name":"RUSSIA"}, ...]`.

## Сделано (было в "известных местах", проверено рабочим прогоном)

1. ✅ Ретрай только на транспортные ошибки, 5xx и 429 (с уважением к `Retry-After`) —
   `stalcraft.py`. На 4xx (кроме 429) падаем сразу.
2. ~~Лоуверкейсить регион~~ — не требуется, API регистронезависим (см. факты выше).
3. ✅ `print()` -> stdlib `logging`, настроено в `main.py`.
4. ✅ SSL на Windows: `app/http.py` мёржит certifi с системным хранилищем сертификатов —
   иначе `CERTIFICATE_VERIFY_FAILED` под антивирусом/корпоративной сетью с TLS-инспекцией.

## Осталось (реальный бэклог)

1. Быстрый выброс между опросами: `currentStart` не увидим — при смене `previousStart`,
   которого не видели живым, слать WARNING постфактум (логика в tracker, время — аргументом).
2. Рестарт во время активного выброса шлёт WARNING заново — guard "не анонсить, если
   currentStart старше N минут" (N в config, "сейчас" — аргумент в tracker). На демо это не
   проверить осмысленно (currentStart там всегда "свежий"), тестировать через мок в tracker.
3. Текст события: показывать `HH:MM МСК`, а не сырой ISO.

## Библиотеки

Есть: `httpx`, `python-dotenv`, `certifi` (явно, из-за `app/http.py`), `tzdata` (Windows zoneinfo),
`aiogram==3.15.0` (меню в личке; закреплён — `create_bot` лезет во внутреннее поле сессии ради SSL); dev: `pytest`, `pytest-asyncio`, `respx`.
Добавлять по мере надобности, не раньше:
- `sqlite3` (stdlib) — когда JSON перестанет хватать (подписчики). Без ORM.
- `ruff` (dev) — линт+формат; в коде уже есть `# noqa`.
Не тащить: веб-фреймворк, Celery/Redis, apscheduler, ORM, сторонний враппер stalcraft-api
(aiohttp+pydantic, избыточно для одного эндпоинта — но его схемы удобно подсматривать).

## Стиль

- Комментарии и докстринги по-русски, как в существующем коде.
- Async везде, один `httpx.AsyncClient` на клиента.
- Новые события — через `Event` из tracker, не хардкодить тексты в main.
- Тест на каждое новое правило в `tracker`.

## Деплой

Всегда-живой процесс (systemd `Restart=always` или Docker `restart: unless-stopped`).
Не GitHub Actions cron — минимум 5 мин и дрейф, короткий выброс проскочит.
